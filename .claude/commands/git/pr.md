# /pr - Pull Request 작성

현재 브랜치의 변경사항을 분석하고 PR을 생성합니다.

## 실행

1. **템플릿 읽기**: `.github/pull_request_template.md`를 **Read 도구로 읽는다** (반드시 원본 파일을 읽어야 함)
2. 현재 브랜치와 develop 간 차이 확인 (`git log develop...HEAD`, `git diff develop...HEAD --stat`)
3. **모든 커밋 분석** (최신 커밋만이 아닌 전체)
4. PR 제목 작성: `[level] 설명` (커밋 메시지 형식과 동일)
5. PR 본문 작성: **읽은 템플릿의 모든 섹션을 빠짐없이 채운다**
6. 푸시되지 않은 커밋이 있으면 먼저 푸시 (리모트 브랜치 없으면 `-u` 플래그)
7. `gh pr create --base develop` 실행

## 작성 원칙

1. **Why 중심**: "무엇을 했는지"보다 "왜 필요한지"를 먼저 설명
2. **구체적으로**: placeholder·주석 문구 남기지 않고 실제 내용으로 채움
3. **테스트 가능하게**: 리뷰어가 그대로 따라하면 검증할 수 있는 수준으로 작성
4. **해당 없음 명시**: 변경이 없는 섹션은 `해당 없음` 또는 삭제
5. **포맷팅**: 명령어·파일명·환경변수는 백틱, 변경 파일이 많으면 카테고리별 그룹핑

## 주의사항

- **템플릿 인라인 복사 금지** — 반드시 `.github/pull_request_template.md` 파일을 읽어서 사용
- 베이스 브랜치는 `develop`
- Co-Authored-By 줄 추가 금지
