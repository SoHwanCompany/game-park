# /roadmap - 로드맵 관리

현재 로드맵 상태를 확인하고, 다음 작업을 제안하거나, 태스크 상태를 업데이트합니다.

## 사용법

```
/roadmap              # 현재 스프린트 상태 확인 + 다음 작업 제안
/roadmap update       # 완료된 태스크 체크 및 상태 업데이트
/roadmap next         # 다음 작업을 즉시 시작
/roadmap plan         # 다음 스프린트 계획 수립
```

## 실행

### 기본 (`/roadmap`)

1. `docs/roadmap.md`를 Read 도구로 읽는다
2. "현재 스프린트" 섹션을 확인한다
3. 상태 요약을 출력한다:
   - 현재 스프린트 이름
   - 전체 태스크 수 / 완료 수 / 진행 중 / 미완료
   - 진행률 (%)
4. 다음 작업을 제안한다:
   - `[~]` 진행 중 태스크가 있으면 이어서 진행 제안
   - 없으면 `[ ]` 미완료 태스크 중 우선순위가 높은 것 제안
   - 현재 스프린트가 모두 완료되었으면 다음 스프린트 시작 제안
5. 사용자에게 "바로 시작할까요?" 확인

### update (`/roadmap update`)

1. `docs/roadmap.md`를 읽는다
2. 최근 git 커밋 내역을 확인한다 (`git log --oneline -20`)
3. 커밋 내용과 로드맵 태스크를 매칭한다
4. 매칭된 태스크를 `[x]`로 변경하고 날짜를 기록한다
5. 변경 사항을 사용자에게 보여주고 확인 후 파일 업데이트

### next (`/roadmap next`)

1. `/roadmap` 기본 실행으로 다음 작업을 식별한다
2. 확인 없이 바로 해당 작업을 시작한다
3. 작업에 적합한 워크플로우를 자동 선택한다:
   - 새 기능 → `/office-hours` → `/brainstorm` 흐름
   - 버그/보안 수정 → 바로 구현
   - UI 개선 → `/code:design` 흐름
4. 작업 완료 시 로드맵 태스크를 `[x]`로 업데이트

### plan (`/roadmap plan`)

1. 현재 스프린트 완료 상황을 확인한다
2. 다음 스프린트의 태스크를 검토한다
3. 우선순위 조정이 필요한지 사용자와 논의한다
4. 필요시 태스크 추가/제거/이동

## 출력 형식

```
## 📋 로드맵 상태

### 현재: Sprint 1 — Critical 수정 및 기반 구축
진행률: ████████░░ 8/11 (73%)

✅ 완료 (8)
- [x] Play Count API 인증 추가 (2026-04-15)
- ...

🔄 진행 중 (1)
- [~] GA4 설치

⬜ 미완료 (2)
- [ ] 실제 게임 3개 연동
- [ ] 게임별 점수 정규화 설정

### 💡 다음 작업 제안
> GA4 설치가 진행 중입니다. 이어서 진행할까요?
> 아니면 "실제 게임 3개 연동"을 시작할까요?
```

## 주의사항

- 로드맵 파일 경로: `docs/roadmap.md`
- 스프린트 순서를 건너뛰지 않는다
- 태스크 완료 시 반드시 날짜를 기록한다
- 새 태스크 발견 시 적절한 스프린트에 추가한다
