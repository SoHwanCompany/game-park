# /commit - 커밋 작성

현재 변경사항을 분석하고 프로젝트 컨벤션에 맞는 커밋을 생성합니다.

## 규칙

1. 커밋 메시지 형식: `[level] 설명`
2. Levels: feat, bugfix, refactor, style, docs, chore, config, add
3. 설명은 한글로 작성
4. Co-Authored-By 줄 추가 금지

## 핵심 원칙: 기능 단위 커밋

- **하나의 커밋 = 하나의 기능/변경 목적**
- 여러 기능이 섞여 있으면 반드시 분리하여 커밋
- 리팩터링과 기능 추가가 함께 있으면 리팩터링 먼저, 기능 추가를 다음 커밋으로
- 변경 파일이 많아도 하나의 목적이면 하나의 커밋으로 OK
- 파일 하나에 여러 목적의 변경이 섞여 있으면 `git add -p`로 hunk 단위 스테이징

## 실행

1. `git status`와 `git diff`로 변경사항 확인
2. **변경사항을 기능/목적별로 분류** — 여러 기능이 섞여 있는지 분석
3. 섞여 있다면 사용자에게 분리 커밋을 제안
4. 각 커밋 단위별로:
   - 해당 파일만 스테이징 (혼합 파일은 `git add -p` 사용)
   - 변경 내용에 맞는 level 선택
   - 간결하고 명확한 설명 작성
   - 커밋 실행
5. 스테이징되지 않은 파일이 있으면 사용자에게 확인

## 예시

```
[feat] 장바구니 컴포넌트 구현
[bugfix] 헤더 스크롤 버그 수정
[refactor] 인증 로직 리팩터링
[style] 버튼 호버 스타일 수정
[docs] README 업데이트
[chore] 불필요한 의존성 제거
```
