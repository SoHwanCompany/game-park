# /qa - QA 검증 (Review 단계)

변경 사항의 영향 범위를 분석하고 시나리오 기반 QA를 수행합니다.

**qa-engineer 서브에이전트**에게 위임하여 격리된 컨텍스트에서 동적 결함을 검증합니다.

## 사용법

```
/qa                                          # 현재 git diff 기준 QA
/qa src/app/[locale]/(main)/games/           # 특정 경로 QA
```

## 실행

1. `git diff --name-only`로 변경된 파일 목록 확인 (인자가 없을 때)
2. **qa-engineer 서브에이전트**를 호출하여 QA 위임
   - 인자로 파일 경로가 있으면 해당 경로를 검증 대상으로 전달
   - 없으면 변경된 파일 목록을 검증 대상으로 전달
3. 서브에이전트가 다음을 수행:
   - **영향 범위 분석**: 변경 파일 → 의존 파일 → 영향 기능 추적
   - **시나리오 설계**: Happy Path / Edge Case / Regression 시나리오 도출
   - **테스트 실행**: 관련 단위 테스트 및 E2E 테스트 실행, 커버리지 갭 식별
   - **게임 플랫폼 검증**: iframe, postMessage, 점수 제출 등 해당 시 검증
4. 서브에이전트의 검증 결과를 PASS / WARN / FAIL 판정과 함께 전달
5. FAIL 판정 시 사용자에게 수정 여부를 확인

## /qa vs /review 비교

| 항목          | /qa                             | /review                        |
| ------------- | ------------------------------- | ------------------------------ |
| **관점**      | 사용자/QA 관점 (동작하는가?)    | 개발자 관점 (코드가 올바른가?) |
| **범위**      | 영향 범위 전체 (의존 파일 포함) | 변경된 파일 중심               |
| **검증 유형** | 시나리오 기반 동적 검증         | 컨벤션/패턴 기반 정적 리뷰     |
| **에이전트**  | qa-engineer                     | code-reviewer                  |

## 권장 순서

```
코드 수정 → /qa → /review → /validate → /commit
```

- **/qa**: 변경이 기능적으로 올바른지 시나리오 검증
- **/review**: 코드 품질과 컨벤션 준수 여부 리뷰
- **/validate**: lint, type-check, knip 정적 검사
- **/commit**: 검증 완료 후 커밋
